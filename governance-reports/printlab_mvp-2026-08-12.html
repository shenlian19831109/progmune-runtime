三、发现了什么

🔴 高可信发现（真实安全/协议问题）

🔴 JWT 算法白名单缺失 — sdk.ts, auth.utils.ts
jwtVerify 调用未指定 algorithms 参数。攻击者可通过 none 算法绕过签名验证——这是可被利用的真实安全漏洞。
✓ 高可信 已验证源码中的 jwtVerify 调用
🔴 通知发送缺少合成步骤 — email-service.ts, notification-log-service.ts
sendOrderStatusNotification 直接调用了 nodemailer.sendMail，但未先执行 composeNotification 来构建邮件内容。共 16 处。
✓ 高可信 协议状态机要求 NOTIFICATION_COMPOSED → NOTIFICATION_SENT 转移
🔴 订单创建跳过成本估算 — routers.ts, order-payment-router.ts, payment-alipay.ts, payment-wechat.ts
createOrder 在 estimate_cost（GCode 材料成本估算）之前被调用。3D 打印涉及实际材料消耗，成本估算应该在订单创建之前完成。共 8 处。
✓ 高可信 协议状态机要求 COST_ESTIMATED → ORDER_CREATED 转移
🟠 支付回调缺少接收步骤 — payment-callbacks.ts, payment-alipay.ts, payment-wechat.ts
verifyCallback 在 receive_payment_callback 之前被调用。签名验证应该先确认回调已接收。共 4 处。
✓ 高可信 协议状态机要求 PAYMENT_CALLBACK_RECEIVED → PAYMENT_CONFIRMED
🟡 服务器启动缺少 TLS 配置 — index.ts
server.listen 在 load_tls_config 之前被调用。共 3 处（开发环境通过反向代理处理 TLS）。
⚠ 需确认 开发环境可接受；生产环境需通过反向代理

⚠️ 需要人工确认

🟡 文件同步 API 误报 — vite.config.ts, vite.ts
fs.writeFileSync 和 fs.promises.readFile 是 Node.js 便捷 API，内部自动完成 open→write/read→close。SSG 状态机不应要求这些同步 API 先调用 open。共 5 处。
⚠ 误报 建议从别名表中移除同步 API
🟡 tRPC 认证模式未识别 — index.ts
Express 检测器报告无认证中间件，但项目通过 tRPC 的 protectedProcedure 和 adminProcedure 处理认证。
⚠ 误报 检测器不认识 tRPC 模式
