# Phase 0: Progmune 科学化衡量标准

> 目标：在进入 Phase 1-4 之前，用 1-2 天明确"科学化"的操作性定义。
> 没有这个标准，"科学化"会退化为标签，而非实际转变。

---

## 1. 核心判定标准

| 维度 | 工程化（当前） | 科学化（目标） |
|------|--------------|--------------|
| **规则操作** | 加规则 → 测 F1 → 不好就回滚 | 预测新规则对 F1 的期望贡献 → 加规则 → 验证预测 |
| **覆盖度** | "我们有 68 条规则，覆盖了 TLS/SSH/HTTP" | "68 条规则覆盖了 TLS 状态空间的 X%，置信度 Y%" |
| **FP 控制** | VI 逐条抑制 FP（43% 减少，经验驱动） | 给定协议复杂度 N，理论 FP 下界 = f(N)，当前距下界还有 Z% |
| **性能预测** | "curl F1=36%，libssh F1=41%——不同 repo 表现不同" | "给定 repo 的协议使用特征向量，预测 F1 范围 ±Δ" |
| **知识增长** | "下个 quarter 加 10 条规则" | "规则完备性缺口 = {具体协议 × 具体状态}，优先级排序由 ROI 公式驱动" |

---

## 2. 各阶段科学化成功标准

### Phase 1: 状态空间覆盖度（2-3 周）

**输入**：现有 Trajectory Corpus（~9 个 session，~2,558 条轨迹）、protocols.json（71 状态 × 109 规则 × 17 namespace）

**成功标准（至少达成 2/3）**：

- [ ] **S1.1** 建立 Trajectory→Coverage 的数学关系：给定 N 条轨迹，协议覆盖率 C 的置信区间 [C_low, C_high] 可以被计算（不是拍脑袋）
- [ ] **S1.2** Trust Report 的 Confidence 字段从定性（HIGH/MEDIUM/LOW/UNCERTAIN）升级为"覆盖度 63% ± 12%（基于 2,558 条轨迹）"——用户能看到数字来源
- [ ] **S1.3** 对 C benchmark（F1=23.3%）给出理论解释：当前 F1 低不是"系统不好"，而是"协议覆盖率只有 X%，需要 Y 条额外轨迹才能达到 Z% F1"

**判定为"不科学"的 red flag**：Coverage 数字无法追溯到轨迹数据，或者置信区间是固定常数。

---

### Phase 2: 验证理论白皮书（2-3 周）

**成功标准**：

- [ ] **S2.1** 白皮书包含一个可被独立验证的核心定理（例如"在协议状态空间 S 中，给定规则集 R，完备验证的充分条件是……"），不是纯叙述
- [ ] **S2.2** 定理的推论可以直接解释至少一个现有 benchmark 现象（如"为什么 curl F1<libssh F1"——因为 curl 的协议使用复杂度是 libssh 的 2.3 倍）
- [ ] **S2.3** 定理可以产生一个可证伪的预测（如"如果增加 N 条 auth 相关规则，F1 预估提升 Δ"），并在 Phase 1 数据上做 back-test

**判定为"不科学"的 red flag**：白皮书只是重新叙述现有 benchmark 结果，没有可证伪预测。

---

### Phase 3: 推理链可解释性（2 周）

**成功标准**：

- [ ] **S3.1** `ViolationTrace` 在 engine 层是一等类型（不是字符串拼接），包含中间状态的序列化表示
- [ ] **S3.2** 对同一条违规，一名未读过 protocols.json 的工程师可以在 2 分钟内理解违规的因果链
- [ ] **S3.3** Trace 长度与违规理解时间之间不再是指数关系（即"推理步数灾难"被解决——长 trace 的理解时间线性增长而非爆炸）

**判定为"不科学"的 red flag**：Trace 只是把已有字段用箭头连起来，工程师仍然需要去查 RFC 才能理解。

---

### Phase 4: 飞轮定性建模（1 周）

**成功标准**：

- [ ] **S4.1** 四飞轮的依赖关系图（DAG），每条边标注耦合机制（如"覆盖率飞轮 → 学习飞轮：提供更多样化的训练轨迹"）
- [ ] **S4.2** 每个飞轮有 1-3 个可测量的关键度量（如学习飞轮：Pairwise Preference Accuracy），当前基线值记录
- [ ] **S4.3** 识别至少一个飞轮间的"瓶颈依赖"（如"覆盖率飞轮不提升，学习飞轮的数据多样性上限为 X"）

**判定为"不科学"的 red flag**：飞轮图是单向箭头堆砌，没有可测量的度量。

---

## 3. 全局判定：Progmune 是否已科学化？

在 Phase 1-4 全部完成后，用以下标准做总体验收：

| # | 标准 | 验证方式 |
|---|------|---------|
| G1 | 系统行为可以被理论预测（不只是事后解释） | 任意新 repo：预测 F1 → 实测 F1，误差在 ±Δ 内 |
| G2 | 规则完备性有可量化的缺口地图（不是"我们还缺规则"） | 缺口 = {协议, 状态, 优先级, 预估 F1 增益} 的排序列表 |
| G3 | Confidence 不是标注，是计算值 | 每条 Trust Report 的 Confidence 可追溯到轨迹覆盖度 |
| G4 | 知识增长有 ROI 公式驱动（不是"下个 quarter 加 10 条"） | 规则增长 → F1 增长的预测误差 < 30% |
| G5 | 存在至少一个被实验验证的可证伪预测 | 白皮书中的预测 → 实际测量 → 记录偏差 |

## 4. 当前基线（2026-08-01，科学化前）

| 度量 | 当前值 | 备注 |
|------|--------|------|
| C benchmark F1 | 23.3% (v6) | 232 sequences, P=15.2%, R=50.0% |
| Cross-repo avg F1 | ~39% (pre-VI) | curl 36%, libssh 41% |
| 协议规则数 | 109 rules, 71 states, 17 namespaces | protocols.json |
| 轨迹总量 | ~9 sessions, ~2,558 trajectories | 分散在 corpus 中 |
| FP 根因 | 71% entity whitelist, + verb generalization gap | root-cause-analysis.json |
| VI FP 减少 | 43% (68/158 FPs suppressed) | cross-repo 汇总 |
| 覆盖度量化 | 无——当前只有定性描述 | 这是 Phase 1 要解决的 |
