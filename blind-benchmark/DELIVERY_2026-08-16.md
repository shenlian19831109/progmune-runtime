## 统一架构：提取器标记模式

所有 11 个扩展共用一个模式——**Python 提取器做源码级分析 → 合成标记调用 →
规则以标记为 trigger（safeguards 置空）**。零下游管道改动。承载的能力包括：
污点追踪（request 根、单跳赋值、os.path.join 链）、限定调用链、import 解析、
跨模块常量解析、模板层扫描（XSS 跨文件）、装饰器检测（csrf_exempt）、
分支语义（GET 状态变更、is_authenticated 守卫）。

## 过程中发现并修复的系统性问题

1. 提取器 O(n²) 类检测（fastapi 卡死）→ 单遍 parent map
2. 测试/文档目录占 66% 噪音 → 非生产面排除（相对路径判断）
3. 类名泄漏（SetCommands.srem 经类词触发 set 动词）→ trigger 只看方法名
4. identifierParse 拆词陷阱（execute_command → SQL trigger）→ triggerCallsOnly
5. marker 自压制（hardcoded_secret 拆出 "secret" 命中自身 safeguard）→ marker 规则 safeguards 置空
6. 两条死规则复活（Dynamic Code Execution / Hardcoded Secrets 的源码级 trigger 在 call-name 接口永远匹配不到）
7. 误标纠正：6 个"无鉴权"TP 实际检查了 is_authenticated（真实缺陷是 cookie 授权）→ 新 cookie 授权规则以正确类别恢复
